# Complete IELTS + PTE lesson-by-lesson editorial queue (repository baseline)

**10 November 2026.** Read-only baseline from `data/ielts-lessons.json`, `data/pte-lessons.json`, and `sitemap.xml`. This is an **inventory**, not an approval to publish 99 generic articles.

**Catalog:** 72 IELTS entries (72 marked published); 27 PTE entries (26 marked published, 1 draft). Repository JSON notes fields are empty across both catalogs; the **separate live classroom API** is the source to verify before writing from notes.

**Critical finding:** The sitemap already lists separate IELTS lesson URLs. Replacing them or creating another URL for the same task risks duplication. The generated IELTS lesson template also contains repeated general study advice. Prioritize distinct examples and teaching interpretation per lesson, with lesson notes and classroom links. Don't mistake template volume for original content.

**Process without per-lesson approvals:** Each queued lesson gets source-note/video verification → a student question and unique answer/example → overlap check → editorial/official rules check → code QA → a single consolidated pull request. Only complete, verified pages graduate to publication; problematic/draft lessons are flagged, not fabricated. Search phrases are editorial hypotheses until confirmed by GSC or documented learner questions.

**Priority order:** A: high-specificity IELTS Reading and PTE task issues; B: Writing/Listening/Speaking deep guidance; C: foundational grammar and broader strategy pages where one group hub may be better than many individual URLs.

## Technical and verification gates

1. Run `python3 automation/knowledge-library-inventory.py` locally/CI for file and sitemap auditing. Add `--live` only where API access works. Results are stored in `docs/seo/knowledge-library-full-inventory.json` by the script.
2. Validate and record current classroom counts independently. The October 27 production audit (63 IELTS and 19 PTE) conflicts with today's repository catalogs (72 IELTS and 26 published PTE); they may reflect different timestamps or storage sources.
3. Resolve exact URLs for overlapping task guides; use links/canonicals as appropriate after verifying index status and user intent, never a blind redirect.
4. Page must have a distinct student question, accurate instructor-sourced explanation, original worked example, correct deep-link, visible review date and optional official reference. No made-up statistics, band guarantees or visa figures.
5. Test mobile, accessibility, link/deep-link behaviour, duplicates, sitemap, and Search Console before merge. Do not auto-merge or auto-deploy this draft.
